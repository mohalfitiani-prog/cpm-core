# إعداد Firebase للنسخة المعاد بناؤها

المشروع الحالي: `cpm-core`. لا تنشئ مشروع Firebase جديداً.

ملف إعداد تطبيق أندرويد موجود في المصدر. يلزم حساب يملك صلاحية نشر Cloud Functions قبل أن تعمل طلبات المشاريع في التطبيق.

## نشر وظائف الخادم

من Cloud Shell أو جهاز عليه Node.js، داخل نسخة مستودع المشروع وعلى فرع `flutter-rebuild`:

```bash
npx --yes firebase-tools login --no-localhost
bash tools/deploy-functions.sh
```

يسجّل الأمر الأول الدخول إلى حساب Google داخل نافذة المتصفح. لا ترسل كلمة المرور أو رمز الدخول في المحادثة.

السكربت يفحص اسم المشروع، يشغّل اختبارات الخادم، يضبط مفتاح Firebase العام في `CPM_WEB_API_KEY` من إعداد أندرويد، ثم ينشر وظائف `cpm-flutter` فقط. قد يطلب Firebase إعداد الخدمات اللازمة أو تفعيل خطة تدعم Cloud Functions؛ راجع أي تغيير فوترة قبل قبوله.

## قواعد قاعدة البيانات والملفات

يستخدم هذا التطبيق Cloud Functions لقراءة وكتابة بيانات المشاريع، ولا يحتاج قراءة مباشرة من تطبيق Flutter إلى Firestore أو Storage.

ملفا `firestore.rules` و`storage.rules` يمنعان الوصول المباشر. يجب مراجعة القواعد الموجودة حالياً وأي تطبيق آخر يستخدم المشروع قبل نشرهما. سكربت نشر الوظائف لا يستبدل هذه القواعد.

بعد التأكد أن القواعد المقترحة مناسبة للمشروع:

```bash
npx --yes firebase-tools deploy --project cpm-core --only firestore:rules,storage
```

لا تختبر النسخة ببيانات حقيقية قبل تطبيق قواعد تحمي بياناتها.

## الحسابات والإدارة

- فعّل Email/Password في Firebase Authentication.
- لتسجيل الدخول بالهاتف، فعّل Phone وسجّل بصمات SHA الخاصة ببناء أندرويد، ثم وثّق الهاتف من داخل التطبيق.
- أنشئ حساب الإدارة في Firebase Authentication، ثم شغّل من بيئة إدارية موثّقة:

```bash
node tools/provision-admin.mjs FIREBASE_USER_UID
```

- لوحة الإدارة موجودة في `flutter_app/lib/admin.dart`. معرّف Firebase Web App الخاص بتطبيق **CPM Core Admin** الحالي هو `1:936725772955:web:0945482389d53f8868e43e`؛ مرّره عبر `FIREBASE_WEB_APP_ID` عند البناء.
- يستطيع مدير النظام تفعيل اشتراك المكتب بعد تسجيل المكتب.

## ما لم ينفّذه النشر تلقائياً

الحسابات القديمة المخزّنة في Room على الهاتف لا تنتقل إلى Firebase تلقائياً. يلزم إعداد مسار ترحيل منفصل للبيانات القديمة. لا تستخدم حسابات العرض وكلمات المرور الافتراضية من نسخة Kotlin للإنتاج.

لم تُختبر هذه النسخة على هاتف فعلي أو مع Firebase المنشور بعد. ملف APK الناتج من GitHub Actions مخصص للاختبار وموقّع بمفتاح debug.
